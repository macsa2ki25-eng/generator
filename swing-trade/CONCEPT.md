# 日本株スイングトレード・アドバイスアプリ 構想書

自分専用の、日本株スイングトレード支援ツール。JPX日経400を監視対象とし、
テクニカル指標に基づく機械的なエントリー/イグジット判断と、
iSPEED風のチャート閲覧・スクリーニング・セクター資金フロー監視を提供する。

**設計の核**: 一度出したシグナルは「トレードシナリオ」として永続化し、
毎日上書きせずに追跡する。根拠が崩れたら明示的に知らせ、
保有銘柄には毎日ジャーナル(日誌)形式でコメントを付ける。

---

## 1. 目的とゴール

- **機械的なトレード**: 感情を排し、明文化されたルールでエントリー・イグジットを判断する
- **毎日の運用イメージ**: 引け後にアプリを開く →
  ①市況・セクター資金フローを確認 →
  ②「明日のエントリー候補」に条件付き注文プラン(こうなったら買い)が並ぶ →
  ③保有銘柄それぞれに今日のジャーナル(継続/利確/損切り判定+コメント)が付いている
- **閲覧機能**: 銘柄ごとのメインページで、日中足・日足・週足・月足のローソク足、
  出来高、移動平均線、価格帯別出来高を一画面で確認できる
- **検証可能性**: すべてのルールはバックテストで過去成績を確認してから採用する

## 2. 前提と正直な注意点

### 勝率について
- 「必ず勝てるルール」は存在しない。評価は勝率単体ではなく
  **期待値**(勝率 × 平均利益 − 敗率 × 平均損失)と **最大ドローダウン** で行う
- 過剰最適化を避けるためルールはシンプルに保ち、検証期間を
  「最適化用」と「確認用(アウトオブサンプル)」に分ける。手数料・スリッページ込みで検証する
- 成績を最も左右するのは資金管理。ポジションサイズ計算をアプリに組み込む

### 「見守り」の実体について(継続性の正直な説明)
- 毎日の判定・コメント生成は**アプリのルールエンジン**が行う(決定論的・忘れない・毎日確実)。
  Claude(私)が毎晩リアルタイムに見ているわけではない
- ただし全シナリオとジャーナルはDBに永続化されるので、Claude Codeセッションを開けば
  私がいつでも履歴を読んで、経緯を踏まえた相談に乗れる
- 判断そのものはルールエンジンに固定する(LLMに判断させると「機械的」でなくなりブレるため)。
  文章表現を豊かにするClaude API連携はPhase 5のオプション

### データについて
- シグナル判定は**日足確定ベース(引け後バッチ)を基本**とする。
  スイングトレードなら日足ベース判断で十分機能し、検証もしやすいため
- 「直近約60日分しか取れない」制約があるのは**分足(日中足チャートの表示用)だけ**。
  日足・週足・月足は20年以上の履歴が取得できる。
  シグナル判定とバックテストはすべて日足系で行うため、確度の問題はない
- 「機械的なエントリー/イグジット」の実運用: アプリは前夜に「逆指値◯◯円で買い」
  「ストップ△△円」という注文プランを出し、**翌朝、証券会社アプリに注文を置けば
  日中の執行は証券会社側で機械的に行われる**。日中に画面を見張る必要はない設計
- 価格帯別出来高はティックデータなしでは厳密には出せない。四本値+出来高から近似計算する
- 売買代金は「終値×出来高」で近似する(公式値とは僅差)

### 法律面
- 自分専用ツールなら投資助言業の登録は不要。第三者への配布・助言提供は
  金融商品取引法に抵触しうるため、**自分用に留める**

## 3. データソース戦略

**確定方針**: 日足系の本番データは最初から **J-Quants API ライトプラン
(JPX公式、月額約1,650円)** を使う。公式の調整済み株価(分割・併合を正しく処理)、
安定したAPI、決算発表予定日、33業種つき銘柄マスタが手に入り、
シグナルの土台として信頼できる。

| ソース | 費用 | 用途 |
|---|---|---|
| J-Quants ライト | 約1,650円/月 | **本番の日足**(週足・月足は日足から合成)、銘柄マスタ(33業種)、決算発表予定日、財務情報 |
| yfinance | 無料 | ①日中足チャート表示(5分/15分、直近約60日・約20分遅延) ②バックテスト用の長期日足(20年以上) |
| JPX日経400 構成銘柄リスト | 無料 | ユニバース定義(年次入替に追従) |
| 証券会社API (kabuステーション等) | 口座があれば無料 | リアルタイム日中足が必要になったら将来検討 |

### J-Quantsライトの限界(把握した上で採用する)
- **分足データはどのプランにもない**。日中足チャートはyfinanceで補う
- **日足履歴は約5年**(プラン仕様は実装時に最新を確認)。それより深いバックテストは
  yfinanceの長期日足で行い、**両ソースが重なる期間で計算結果が一致することを
  確認してから**使う(データ品質のクロスチェック)
- 日足の配信は夕方以降 → 引け後バッチの運用と整合する

## 4. 対象ユニバースとフィルタ

- **JPX日経400 構成銘柄**(手動での追加・除外も可能)
- **流動性フィルタ**(書籍準拠): 1日平均出来高 50万株以上を推奨対象とする。
  出来高が少ない銘柄はテクニカルが機能しにくいため、候補から除外 or 減点

## 5. セクター/資金フロー監視

ニュース等のファンダメンタルズは追わない代わりに、
**「今どの業種にお金が入っているか」を数字で掴む**。テクニカル判断の邪魔はせず、
むしろ「強いセクターの強い銘柄を買う」形でスコアに組み込む。

### 市況・セクターページ(新設)
- **東証33業種ヒートマップ**: 当日騰落率で色分け。期間切替(1日/1週/1ヶ月)
- **業種別売買代金ランキング**: 当日の売買代金と、20日平均比(◯倍)。
  平均比が高い業種=資金流入中、と読む
- **資金フローの推移**: 業種別売買代金シェアの時系列グラフ。
  「どこからどこへ資金が移っているか」の流れを可視化
- **セクター相対強度(RS)**: 各業種指数(構成銘柄から算出)÷ TOPIX の相対チャートとランキング

### 戦略への組み込み方
- 銘柄シグナルのスコアに**セクターRS加点**: 所属業種が1ヶ月RS上位1/3なら加点、下位1/3なら減点
- 銘柄ページに所属業種と業種内順位を表示
- あくまで加点要素であり、テクニカル条件を満たさない銘柄が候補に入ることはない

## 6. 機能一覧(画面構成)

### 6.1 明日のエントリー候補(トップページ)
夜間バッチが生成する「**明日、こうなったら買い**」の注文プラン一覧。銘柄ごとに:
- シグナル種別とスコア(セクターRS加点込み)
- **エントリー条件**: 「◯◯円を上抜けたら逆指値買い」「寄り成行(ただし△△円以上に窓を開けたら見送り)」など発注にそのまま使える形
- **損切り価格**(初期ストップ)と根拠(例: ジャンプ台=20日線割れ)
- **利確目安**(前回高値・節目など)とリスクリワード比
- **推奨株数**(資金管理設定から自動計算)
- 条件が成立しなかった場合の扱い(何日待つか)も明記

### 6.2 銘柄メインページ(iSPEED風)
- ローソク足: 日中足(5分/15分)・日足・週足・月足をタブ切替
- 移動平均線(書籍の配色に合わせる): **赤=5日(1週)、緑=20日(1ヶ月・ジャンプ台)、青=60日(3ヶ月・トレンド)**。週足・月足は別途設定
- 出来高バー、**価格帯別出来高**(右側横向きヒストグラム)
- 売買代金(20日平均比つき)、所属業種とセクターRS
- この銘柄のアクティブなシナリオとジャーナル(下記)を同画面に表示
- シグナル地点マーカー、エントリー/ストップ/ターゲットの水平線

### 6.3 スクリーニング
- 条件フィルタ: トレンド状態、20日線への接近度(押し目候補)、出来高急増、
  新高値接近、売買代金、セクターRS、等
- 「セットアップ接近ウォッチ」: まだシグナル前だが条件成立が近い銘柄の監視リスト
  (例: 押し目候補が基準線に接近している、ブレイク候補が高値圏で煮詰まっている)

### 6.4 ポジション管理+ジャーナル
- 保有銘柄を登録(取得単価・株数)。エントリー候補からワンクリックで建玉化
- 毎日の判定: **「継続」「利確」「半分利確」「損切り」「ストップ切り上げ」**
- **日次ジャーナル**(後述)を銘柄ごとに時系列表示

### 6.5 市況・セクター(セクション5の内容)

### 6.6 バックテスト
- 戦略・期間・ユニバースを指定して過去シミュレーション
- 出力: 期待値、勝率、プロフィットファクター、最大ドローダウン、トレード一覧、資産曲線

## 7. 継続性の設計: トレードシナリオとジャーナル(このアプリの心臓部)

「毎日上書きして目線がその日からになる」問題を防ぐため、
シグナルは使い捨てにせず**シナリオ(トレード仮説)として永続化**する。

### シナリオオブジェクト
シグナル発生時に以下を記録し、以後は**このシナリオを基準に**毎日評価する:
- 作成日、銘柄、セットアップ種別
- **エントリー根拠のスナップショット**(当時のMA値、押し安値、出来高状況、セクターRS)
- エントリー条件、初期ストップ、利確目安
- **無効化条件の明文化**(例:「終値で20日線を割る」「60日線が下向きに転じる」
  「候補のまま5営業日経過」)— 何が崩れたら降りるかを最初に決めておく

### 状態遷移
```
候補(watch) → 待機中(エントリー条件監視) → 建玉(保有) → クローズ(理由付き)
                     └→ 失効(根拠崩れ・時間切れ、理由付き)
```
- 毎晩のバッチは新規スキャンとは別に、**既存のアクティブなシナリオを全件再評価**する
- 評価は常に「作成時の根拠がまだ生きているか」に対して行う(その日からの目線にリセットしない)
- 根拠が崩れたら状態を変え、**何が崩れたのかを明記して通知**する

### 日次ジャーナル(追記専用・上書きしない)
建玉と待機中シナリオには毎日1件、日付付きコメントが自動で付く。例:

> **7/10(木) 保有3日目 | 判定: 継続**
> 終値2,845円(+1.2%)。ジャンプ台(20日線 2,790円)の上をキープ、5日線は上向き。
> 出来高は20日平均比0.9倍とやや細るが、エントリー根拠(20日線での反発)は崩れていない。
> ストップ2,760円のまま。利確目安の前回高値2,920円まであと2.6%。上昇カウント4本目。

> **7/11(金) 保有4日目 | 判定: 半分利確を推奨**
> 前回高値2,920円にタッチ後、上ヒゲで2,880円引け。書籍ルールの利確サイン
> (前回高値到達)が点灯。半分利確し、残りはストップを2,820円(エントリー足の安値)へ切り上げ。

- コメントはルールエンジンが実データから生成する(テンプレート+実数値)。
  毎日確実に、全建玉に付く
- クローズ後もシナリオとジャーナルは履歴として残り、事後レビューに使える
  (どの根拠のトレードが勝てているかの統計も取れる)

## 8. 戦略エンジン: 候補を対等に競わせ、データで選ぶ

**主戦略は事前に決めない。** 以下の戦略候補を同一条件のバックテストにかけ、
事前に定めた合格基準を満たしたものだけを採用する。書籍の手法も私の設計案も
対等な「候補」であり、特別扱いしない。

### 選定プロトコル(先に決めておく — 後出しでの基準いじりを防ぐ)
- 検証期間を **最適化用(例: 2016〜2022)** と **確認用(2023〜現在、アウトオブサンプル)** に分割
- 合格基準(初期案): アウトオブサンプルで期待値プラス、プロフィットファクター1.3以上、
  トレード数100件以上(偶然でない標本数)、最大ドローダウンが許容内
- 相場環境別(上昇/下落/レンジ)の成績も確認し、「どんな地合いで機能する戦略か」を明記
- 全候補が不合格なら採用ゼロもあり得る。その場合はルールを見直して再検証
  (**成績の悪いルールでシグナルを出すくらいなら、出さない**)

### バックテストの現実性(甘い想定は成績を偽る)
- **約定の想定は保守的に**: 寄りギャップで逆指値を飛び越えたら寄り値で約定。
  ストップは当日安値が到達していれば約定、窓開け下落時は(ストップ価格ではなく)寄り値で
  約定したとみなす。ストップ安張り付きは翌営業日以降の寄りまで降りられない前提
- 手数料+スリッページを往復で保守的に計上(例: 往復0.2%)
- **生存者バイアス対策**: 現在のJPX400構成で過去を検証すると成績が過大評価される
  (勝ち残った銘柄だけで検証することになるため)。年次入替の公表情報から過去の構成を
  できる範囲で復元し、復元できない期間は「当時の流動性上位銘柄」で代替。
  それでも結果は割り引いて読む
- **過剰最適化ガード**: パラメータ探索は最小限に。最良の一点ではなく
  「周辺の値でも成績が崩れない安定領域」を選ぶ。候補は3つ×少数パラメータに限定する
  (たくさん試すほど、偶然の当たりを拾ってしまうため)

### 候補1: ジャンプ台押し目買い(ぐりーん式 — 書籍のルール化)
- 移動平均: 赤=5日(1週)、緑=20日(1ヶ月・ジャンプ台)、青=60日(3ヶ月・トレンド)
- 青(60日線)上向き+株価がその上で、株価が緑(20日線)に押して**弾かれる**(反発陽線)を買う
- エントリー: シグナル日高値超えの逆指値。時間軸: 1〜2週間
- 損切り: 20日線を終値で割ったら。遠い場合はエントリー足/前の足の安値下、
  または5日線を陰線で割った日(書籍準拠、目安2〜4%下)
- 利確: 高値更新停止 / 前回高値 / 上昇カウント9本目 / 価格の節目 → 決済 or 半分利確
- 注意: 書籍の運用には裁量的なチャート読みが含まれるため、機械化した本ルールの成績が
  著者の成績と一致する保証はない(だから検証する)

### 候補2: ATR適応型トレンド押し目(私案)
- 75日MA上向き+株価がその上、25日MAへの押し目から前日高値超えで反発
- 候補1との本質的な違いは**ボラティリティ適応**: 損切りは固定の線割れではなく
  2×ATR(14)下に置き、銘柄ごとの値動きの荒さに合わせる
- 利確: 2Rで半分利確、残りは10日MA終値割れのトレーリング(利を伸ばす設計)

### 候補3: 出来高ブレイクアウト(私案)
- 直近60日高値を出来高増(20日平均比1.5倍以上)を伴って終値更新
- 価格帯別出来高で上値のしこりが薄いことを加点
- 損切り: ブレイクしたレンジの内側。利確: トレーリング主体
- 押し目型(候補1・2)と性質が異なる(押し目型が機能しない強トレンド相場の補完)

### 共通の防御ルール(全候補に適用 — テクニカルが対処できないリスクをルールで塞ぐ)
- **決算またぎ回避**: 決算発表まで5営業日未満の銘柄は新規エントリー見送り。
  保有中に決算日が来る場合は原則、発表前日までに手仕舞い(または半分に縮小)。
  テクニカルは決算ギャップを予測できない。スイングトレード最大の事故要因への必須の防御
  (決算発表予定日はJ-Quantsから機械的に取得)
- **地合いフィルタ**: 下落地合い(例: TOPIXが60日線の下)では新規エントリーを停止し、
  保有銘柄の管理だけ続ける。個別銘柄がどれだけ良い形でも、地合いが悪ければ
  押し目買いの勝率は大きく下がる。具体的な条件はバックテストで効果を確認して決める
- **セクター分散**: 同一業種への同時エントリーは1銘柄まで
  (最大3銘柄が同じ業種に偏ると、実質1つの賭けになるため)

### その他の共通要素
- 流動性フィルタ(出来高50万株以上)、セクターRS加点、資金管理(下記)
- シナリオには**生成した戦略のタグ**を付け、実運用でも戦略別の成績を集計し続ける
  (バックテストで受かった戦略が実運用で崩れたら気づける)

### 資金管理(確定設定・画面から変更可能)
- 総余力資産: **600万円**
- 1トレード許容リスク: **標準1% = 6万円**(損切り幅3%なら1銘柄あたり約200万円のポジション)。
  ただし実弾開始直後は**0.5% = 3万円**から(下記プロトコル)
- **同時保有は最大3銘柄**(合計リスク3%まで)から開始
- 推奨株数 = 許容リスク金額 ÷ (エントリー価格 − ストップ価格)、単元株に丸め

### 実弾投入までの手順(運用開始プロトコル)
資金を守るため、以下の関門を順に通す。飛ばさない:
1. **バックテスト合格**(Phase 2): 選定プロトコルの基準を満たした戦略のみ採用
2. **フォワードテスト1〜2ヶ月**(ペーパートレード): シナリオエンジンを実弾なしで運用し、
   ジャーナルだけ付ける。バックテストと成績が乖離していないかを確認
   (シナリオ+ジャーナルの仕組みがそのまま検証記録になる)
3. **実弾は許容リスク0.5%(3万円)から**: 5〜10トレード問題なければ1%へ引き上げ
4. **月次レビュー**: 実運用成績とバックテスト想定の乖離を毎月チェック。
   戦略別成績が明確に崩れたら、その戦略を停止して原因を調べる

## 9. 技術構成

```
swing-trade/
├── backend/            # Python (FastAPI)
│   ├── data/           # データ取得層(yfinance実装、J-Quants差替可能に抽象化)
│   ├── indicators/     # MA, ATR, 出来高分析, 価格帯別出来高, 売買代金
│   ├── sector/         # 33業種マスタ, セクター指数・RS・資金フロー集計
│   ├── signals/        # セットアップ判定・スコアリング
│   ├── scenario/       # シナリオ永続化・状態遷移・日次再評価・ジャーナル生成
│   ├── backtest/       # 日足イベントループ型バックテスター
│   └── api/            # REST API
├── frontend/           # 静的HTML/JS(ビルド不要)、lightweight-charts(OSS)を同梱
├── db: SQLite          # 株価キャッシュ・シナリオ・ジャーナル・ポジション
└── 起動: ダブルクリック用の start.command / start.bat
```

## 10. 開発フェーズ

| Phase | 内容 | ゴール |
|---|---|---|
| 1 | データ基盤+銘柄ページ | JPX400のチャート(4時間軸・MA・出来高・価格帯別出来高)が見られる |
| 2 | 戦略フレームワーク+バックテスト | 候補1〜3を同一条件で検証し、合格基準を満たす戦略を**データで選定** |
| 3 | シグナル+シナリオエンジン | 採用戦略で「明日のエントリー候補」が毎日出る。シナリオ永続化・ジャーナルが動く。**まず1〜2ヶ月ペーパートレードで運用** |
| 4 | ポジション管理+セクター監視 | 保有銘柄の日次ジャーナル、市況・セクターページ |
| 5 | 拡張 | J-Quants移行、通知(メール/Discord)、Claude APIによるコメント文章強化 等 |

**バックテストを実シグナル配信より先に置く**(Phase 2→3の順)。
検証していないルールでエントリー候補を出すことはしない。
